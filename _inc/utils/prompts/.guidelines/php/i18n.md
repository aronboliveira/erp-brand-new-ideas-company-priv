# Internationalization (i18n) Guidelines

## Supported Languages

The application supports **16 languages**:

| Code | Language |
|---|---|
| `ar` | Arabic |
| `da` | Danish |
| `de` | German |
| `en` | English |
| `es` | Spanish |
| `fr` | French |
| `he` | Hebrew |
| `it` | Italian |
| `ja` | Japanese |
| `nl` | Dutch |
| `pl` | Polish |
| `pt` | Portuguese |
| `pt-br` | Brazilian Portuguese |
| `ru` | Russian |
| `tr` | Turkish |
| `zh` | Chinese |

## JavaScript Format

Translations are exposed to the front-end via a global `window.translations` object:

```javascript
window.translations = {
    en: { greeting: 'Hello', farewell: 'Goodbye' },
    es: { greeting: 'Hola',  farewell: 'Adiós'   },
    // ... all 16 languages
};
```

Access pattern: `window.translations[lang][key]`

## PHP Format

Server-side translations use a nested associative array:

```php
$translations['main_key']['en']['greeting'] = 'Hello';
$translations['main_key']['es']['greeting'] = 'Hola';
```

Access pattern: `$translations[$mainKey][$lang][$key]`

## DELEGATION_ Constants

Support delegation messages are defined as constants covering all 16 languages.
Each constant provides a pre-translated message for a specific delegation scenario
(e.g., ticket escalation, task reassignment).

These constants follow the naming pattern `DELEGATION_{SCENARIO}_{LANG}` and are
grouped in a dedicated constants class.

When adding new delegation scenarios, **all 16 language variants must be created simultaneously**
to prevent missing-translation errors in production.
